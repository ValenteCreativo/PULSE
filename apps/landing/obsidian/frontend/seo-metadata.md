# SEO & Metadata

## Site config

`src/lib/site.ts` (`siteConfig`) is the **single source of truth** for SEO. The
metadata generator, `robots.ts`, `sitemap.ts`, the JSON-LD helper and the root
layout's `lang` all read from it — nothing it holds is written twice anywhere
else.

| Field | Value |
|---|---|
| `name` | `Codescan` — the studio, and what `%s — Codescan` appends |
| `title` | `Codescan — We make the past feel new` — the home page's full title |
| `description` | the studio in one sentence; used for `<meta>`, OG, Twitter and the OG image's `alt` |
| `url` | `NEXT_PUBLIC_SITE_URL` ?? `https://codescan.studio` |
| `ogImage` + `ogImageSize` | `/open-graph.jpg`, **1200×630** — a capture of the hero (`scaffold-brand.mjs`), declared from the real asset; `ogImageAlt` says what it shows |
| `twitterHandle`, `author` | `@codescan`, `Codescan` |
| `locale`, `language` | `en_US`, `en` |
| `privacyPolicyUrl` | `null` until a policy exists — see below |
| `themeColor` | `#000000` — the room the site opens in |

`name` and `title` are **deliberately two strings**: a home page titled
*Codescan — Codescan* is the classic way a title template goes wrong.

The `url` fallback is the production domain rather than `localhost`, so a build
that forgets the variable still emits absolute URLs that resolve. The trade is
that a preview deploy without it points its canonicals at production — **set it
per environment** ([[environment-variables]]).

`privacyPolicyUrl` is typed `string | null` rather than inferred, so setting it
stays a one-line change. Both consent surfaces read it through
[[components/common|`<PrivacyPolicyLink>`]] and render the phrase as plain text
while it is `null` — an underlined *privacy policy* that 404s is the last thing a
consent banner should carry. ADR: [[decisions-log]] ADR-0037.

> [!note] `ogImageSize` exists because scrapers believe it
> The dimensions are declared to Facebook/X/Slack from the same place the file is
> named. A share card that lies about its own size is cropped by whoever renders
> it. 900×600 is the asset we have; 1200×630 is the ideal if it is ever redrawn.

## Metadata generator

`src/utils/seo/generate-page-metadata.ts` exports two builders:

```ts
import { generateMetadata } from "@/utils/seo/generate-page-metadata";

export const metadata = generateMetadata({ title: "Work", url: "/work" });
```

- `generateMetadata(props?)` → a Next.js `Metadata` object: title/description,
  OpenGraph, Twitter cards, canonical, icons, manifest, robots. `metadataBase` is
  **always set** from `siteConfig.url`, so relative URLs resolve to absolute —
  required by social scrapers.
- `generateViewport()` → the `Viewport` export. `themeColor` lives here, **not**
  on the metadata object (Next deprecated it there).

Options: `title`, `titleTemplate`, `titleAbsolute`, `description`, `url`,
`ogImage`, `twitterHandle`, `author`, `siteName`. **No `keywords`** — every
engine that matters has ignored the tag for a decade, and it was dropped from
this generator on purpose.

### The title template, and who owns it

A template rewrites the titles its **descendants** declare, so exactly one place
in the tree sets one:

- **`app/layout.tsx`** → `generateMetadata({ titleTemplate: "%s — Codescan" })`.
  Its `title.default` is `siteConfig.title`.
- **`app/page.tsx`** → `generateMetadata({ title: siteConfig.title,
  titleAbsolute: true, url: "/" })`. `titleAbsolute` opts out of the template,
  which would otherwise render *Codescan — … — Codescan*.
- **any future route** → `generateMetadata({ title: "Work", url: "/work" })` and
  nothing else; the template supplies the rest.

### What else it emits

- `robots` + a `googleBot` block with `max-image-preview: large` and
  `max-snippet: -1` — Google's defaults for an unseen site are conservative, and
  a site that *is* one long picture wants the whole preview.
- `formatDetection: { telephone: false, … }` — iOS turning stray digits in the
  copy into call links is only ever a false positive here.
- `applicationName`, icons (favicon set + apple touch), `manifest`.

`generateViewport()` sets `width=device-width, initial-scale=1` and **no
`maximumScale` / `userScalable: false`**: pinch-zoom is the one way in for anyone
who needs the type larger than a 360px design draws it, and taking it away is a
WCAG 1.4.4 failure.

## robots.txt & sitemap.xml

Generated by the Next file conventions:
- `src/app/robots.ts` → `/robots.txt` — allows all crawlers, points at the sitemap.
- `src/app/sitemap.ts` → `/sitemap.xml` — lists public routes (home only so far;
  add an entry per route as the site grows).

## Structured data (JSON-LD)

`src/utils/seo/structured-data.ts` builds the graph. Every `@id` is an absolute
URL from `siteConfig.url` and they are exported as `schemaId`, which is what lets
a crawler see **one** organisation described in two places rather than two
organisations.

| Helper | Emits | Rendered by |
|---|---|---|
| `getSiteStructuredData()` | `Organization` + `WebSite`, linked by `publisher` | `app/layout.tsx`, once |
| `getHomeStructuredData()` | `WebPage`, `isPartOf` the site and `about` the organisation | `views/home.tsx` |

The page-level node carries the title, share image and language of *this* URL;
the site-level pair says nothing about any one page. Add one per public route.

> [!important] Nothing in the graph is invented
> No `sameAs` list of profiles the studio does not have, no address it has not
> given. Fabricated structured data is a penalty, not a rich result.

The `WebPage` node is rendered from **the view, not the route file** — `page.tsx`
holds its `metadata` export (Next reads that from the segment itself, so it
cannot move) and nothing else, per hard rule #5 / [[decisions-log]] ADR-0003.

## The other manifests

- `public/manifest.json` — name, description, `start_url`, `scope`,
  `display: standalone`, black background and theme, the six Android icons.
- `public/browserconfig.xml` — the Windows tile. It shipped pointing at three
  `ms-icon-*.png` that were never in `public/`, so every tile request 404'd; it
  names the icons that exist and takes the site's own black.

## Bot detection

`src/utils/is-bot.ts` exports `isBot()` — a **server-only** async helper that
reads the `user-agent` header and returns `true` for Lighthouse, Googlebot,
PageSpeed, HeadlessChrome, GTmetrix, Pingdom, Bingbot, Yandexbot.

> [!caution]
> Calling `isBot()` (or any `headers()` reader) in a route **opts it out of
> static prerendering** — a TTFB cost for every visitor. Serving crawler-specific
> behaviour also borders on cloaking. Prefer the [[animation-system|reduced-motion]]
> path (`<ReducedMotion>`): animations only touch opacity/transform, so content
> is always in the DOM and crawlers see it regardless. Use `isBot()` sparingly.

## Static assets

The `public/` **root** holds meta/PWA/SEO assets — favicons (multiple sizes),
`icon.svg` (the mark, from `src/assets/brand/mark.svg`), Android/Apple icons,
`icon-512.png` / `icon-maskable-512.png`, `manifest.json`, `browserconfig.xml`,
`open-graph.jpg`.
Site **content** assets (images, videos) go under `public/assets/<section>/` —
see [[folder-structure]].

> [!note] Brand kit (2026-10-06, D-033)
> `open-graph.jpg` is **1200×630** and `siteConfig.ogImageSize` declares the same.
> All icons and the manifest are regenerated from `src/assets/brand/mark.svg` by
> `optimization-pipeline/tools/scaffold-brand.mjs` — edit the mark, re-run it.
